Payment gateway testing

Gateway tests should prove message mapping, transport behavior, and transaction recovery across the systems that share responsibility for a payment.

Define the contract first

Document the gateway mode (server, client or proxy), framing, TLS requirements, timeouts, retries, idempotency keys, message format and field mappings. For an ISO 8583 gateway, document the exact dialect—not simply “ISO 8583.” For API gateways, define error schemas and asynchronous callback behavior.

Exercise failure deliberately

  • Connection refusal, TLS failure, broken framing and partial reads.
  • Host timeout and response-after-timeout ambiguity.
  • Malformed, unsupported and internally inconsistent messages.
  • Duplicate delivery, retry and reversal/compensation logic.
  • Masked observability: correlate logs without retaining sensitive payment data.
